# Git化问题与边界（2026-10-15）

- 初查两端root均非Git仓库，rev-parse失败是基线事实，对应run保留；初始化、共享历史导入与提交后检查通过。
- Windows和Ubuntu原有指南/总日志不完全一致。采用共同父提交与独立Ubuntu分支保存实际差异；原文件没有被checkout/reset覆盖；两端账本只分别做历史快照。
- 自动追加总日志会让每条命令产生代码dirty噪声。原账本留在磁盘持续追加并加入ignore，阶段报告进入Git，初始化快照进入history。复验干净运行在两端均dirty=false。
- 只保存HEAD会丢失未提交改动的上下文。增加dirty、状态路径、已跟踪差异patch和SHA，保留原源码快照；真实注释改动测试在两端通过，源码完整恢复。
- 代码、数据和模型分开保存。Git不包含原始采集、权重、环境或所有运行目录；复现实验需结合run_id、输入/权重SHA和已有环境记录。本次没有自动生成本次之前的Git提交，也没有由Git验证6D物理精度。
