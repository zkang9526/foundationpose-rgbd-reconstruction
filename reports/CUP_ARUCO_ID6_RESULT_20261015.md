# ArUco ID 6、黑边实测30 mm：真实杯子位姿初测

2026-10-15已在Ubuntu接入并完成一次D435i实测。结论：可以记录相对漂移，但当前结果不足以验收移动相机的6D精度。单码参考存在明显抖动/姿态跳变，跟踪在末端发生真实失跟。用户随后补充“也有可能是杯子被遮挡了”，作为未确认的现场条件保留。

- Ubuntu：`/data/ZJC/foundationPos`，分支`fix/reacquisition-sam2-eval`，没有合并main。

## 参考本身与跟踪问题

1. **小码参考噪声。** 用户确认停稳后的000004—000234，共231帧、12.078秒。相对第一帧，ArUco平移变化P95 6.42 mm、旋转变化P95 3.00°；FoundationPose自身平移变化P95 1.51 mm、旋转变化P95 5.97°。这描述静止重复性，没有独立GT，不能直接相减得到真实定位误差。码角点变化RMS的P95仅0.56px，表明亚像素变化也会明显影响单码姿态。
2. **参考姿态跳变。** 001906达到127.03mm差异，ArUco相对前帧旋转跳58.64°，FoundationPose同期1.39°；001908的ArUco跳48.96°、FoundationPose1.64°。原RGB存在运动模糊；仅凭低重投影误差和当前平面解门限，仍不能保证选择了正确的平面姿态。尖峰有参考侧跳变参与，不能全部归因于杯子估计。
3. **真实失跟。** 001938，15:58:37.536，GPU数值推理成功，但投影8054像素内有效深度为0，因此隐藏位姿并搜索。该帧全图有效深度仍为40.62%，不是全图都没有深度；RGB/深度SDK时间戳差约0.018ms。原RGB里杯子可见，不能据此排除瞬时遮挡、深度双目侧遮挡或快速运动；用户“可能被遮挡”的反馈未独立验证。缺深度的直接原因仍待查。
4. **恢复未完成。** 7次SAM2搜索，6次输出匹配候选；已消费的6次结果均未提交新注册，其中5次虽有候选但新旧画面特征不足或变化12.14/45.71/74.00px。持续运动使候选过时；最后一次搜索完成时会话已结束。本次不宣称恢复成功，也不能据此判定停稳后必定无法恢复。

当前模型的杯口/接触侧孔洞、杯把方向歧义继续保留；Mask/深度一致性不是6D精度验收。没有独立`T_marker_from_original_mesh`，所以绝对误差字段为null。

建议先改善参考：根据本次小码噪声，优先换更大的实测码或采用尺寸/间距实测的多码板，再核查RGB内参和参考静止重复性。多码板能使用更多角点且允许部分标记不可见，这是[OpenCV官方板检测说明](https://docs.opencv.org/4.x/db/da9/tutorial_aruco_board_detection.html)的适用优势；本项目目前只实现单码参考，没有自动宣称多码板已部署。之后单独做“慢移”“快移”“遮挡后停稳找回”，记录实际阶段起止时间。
