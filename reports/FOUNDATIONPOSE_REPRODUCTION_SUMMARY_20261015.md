# FoundationPose 六维位姿估计项目：工程复现、优化与实验总结

更新日期：2026-10-15。内容依据现有运行档案、源码版本、实际采集和评测报告整理。

## 项目概述

面向没有现成 CAD 的自有杯子，围绕 FoundationPose 官方预训练模型，构建了从 RGB-D 数据获取、目标分割、多视角几何重建，到位姿初始化、实时跟踪、目标重获和相对位姿评测的完整工程原型。工作重点是将开源研究代码适配到真实深度相机场景，并针对环境兼容、参考模型质量、初始化时序、推理吞吐和失跟恢复进行排查与扩展。

**当前交付的是可运行、可分析、可回溯的位姿估计研究原型。** 已完成官方示例小规模验证、自有物体模型接入、真实相机实时推理以及自动重获的回放闭环；最新小幅移动现场会话连续跟踪约 **18.06 FPS**，优化入口在不同回放实验中约 **27–29 FPS**。真实运动测试仍存在朝向漂移，重建模型仍有孔洞，尚未达到高精度、长期稳定的六维位姿验收标准。

本项目使用官方预训练 scorer/refiner，没有针对杯子重新训练位姿网络。无现成 CAD 的阶段先生成候选网格，后续推理采用网格辅助位姿估计；不能将其写成完全不需要模型输入的实时模式。

## 一、核心技术与系统组成

|模块|核心技术|本项目中的作用|
|---|---|---|
|六维位姿估计|FoundationPose、PyTorch、CUDA|全局位姿初始化、候选评分、迭代细化和连续局部跟踪|
|目标分割|SAM ViT-B、SAM2.1 Hiera Tiny|框与前/背景点交互分割；失跟后的全图候选生成|
|三维重建|几何姿态初始化、点到面 ICP、TSDF、Open3D|将多视角有效深度融合为米制候选模型|
|GPU部署与渲染|Docker、NVIDIA Container Toolkit、NVDiffRast、PyTorch3D、Warp|隔离推理依赖，运行 CUDA 扩展、网格投影及几何处理|
|独立参考评测|OpenCV ArUco、PnP、SE(3)/SO(3)变换|分析固定杯子与标记之间的相对位置、朝向稳定性|
|实验管理|Git、源码快照、SHA256、统一运行记录器|绑定代码、输入、权重与输出，保留失败、重试和中断证据|

计算端为 Ubuntu 20.04、RTX 3090 24 GB。FoundationPose 主推理容器保留 Python 3.8 / PyTorch 2.0.0+cu118；BundleSDF 使用独立容器；SAM2 使用独立 Python 3.11 / PyTorch 2.5.1+cu121 环境，避免为新分割模型破坏既有推理依赖。Open3D 原生环境承担几何重建与分析。

## 二、复现流程

### 1. 固定环境与验证官方基线

固定 FoundationPose 官方源码提交和预训练权重，配置 Docker/CUDA 运行环境，编译并检查本地扩展。通过 GPU 运算、可微光栅化、点云算子、模型加载等实际检查后，运行官方 mustard0 示例的首帧初始化和后续两帧跟踪，保存矩阵和叠图。

这一步建立“环境与官方小规模示例能运行”的基线，未将首 3 帧验证扩大为完整 737 帧或论文全部指标复现。

### 2. 建立真实 RGB-D 数据输入

使用 D435i 采集彩色图、深度、SDK 内参、传感器参数与时间戳，深度映射到彩色图像视角并保存为 16-bit 毫米 PNG。原始深度与滤波深度分开保存，缺失值保留为 0。

采集方式从初期试录调整为固定相机、手动旋转杯子、停稳且手退出后触发照片，逐步获得侧面、斜俯视及新的 72 张参考圈。各圈和独立测试分别保存，计划角度仅作采集备注，不用作实测外参或位姿真值。

后续采用静态 PNG 与证据包传入 Ubuntu，逐文件和整包 SHA256 验证，Windows 运行档案按唯一 run_id 追加，避免覆盖服务器已有记录。大体积原生 bag 按用户选择留在 E 盘。当前 Windows 项目与产物统一位于 E 盘，旧 C 盘入口保留为目录联接。

### 3. 从官方重建尝试推进到独立几何方案

首先配置 BundleSDF，分别尝试侧面、斜俯视、冻结神经位姿更新及新 72 帧重建，检查关键帧、位姿变化和多视角网格。初期模型出现折叠、缺口和残缺杯把；新 72 帧虽然真实物体旋转一圈，官方跟踪却只选择 1 个关键帧、最大估计转角约 3.275°。去除 RGB 背景的对照仍未改善，因此没有把官方导出网格视为成功重建。

随后构建独立、针对当前倒扣杯子场景的几何方案：

1. 从有效深度估计可见杯底平面、圆心及杯把方向，形成初始姿态候选。
2. 对遮挡或方向依据不足的帧明确标记插值来源；72 帧中 53 帧有方向候选依据，19 帧插值，不使用 planned_angle。
3. 依据杯体实际深度剔除明显离群点，用有界点到面 ICP 作小幅配准修正。
4. 使用 1.5 mm 体素、7.5 mm 截断的 TSDF 融合，另存碎片清理结果，导出米制 OBJ/PLY。
5. 用多视图轮廓、连通性、完整边界和人工近似尺寸进行检查，不用平滑、缩放或任意补孔伪造未观察表面。

清理后的候选模型包含 **26,731 个顶点、51,318 个面**，杯身与杯把外形较最初重建明显改善。杯口、内壁和支撑接触面仍有观测不足、孔洞与噪声，属于可用于流程实验的候选网格，未验收为精确 CAD。

### 4. 接入自有物体位姿初始化与实时跟踪

将候选网格接入官方 FoundationPose，先对 5 张不参与重建的独立 RGB-D 测试图分别初始化，核对毫米到米转换、相机内参、网格坐标和位姿方向，保存原网格坐标到相机的 4×4 矩阵、框/坐标轴和完整网格投影。

进一步建立 Ubuntu 直连相机实时入口，通过浏览器冻结原始帧、框选目标、生成并确认 Mask，再将同一冻结 RGB-D 输入全局注册，后续调用官方 track。旧 GrabCut 入口保留，快速入口升级为 SAM 框与前/背景点交互分割；提示变化后使旧 Mask 失效，保存每次生成尝试。SAM 在初始化时运行，不在每个跟踪帧重复分割。

### 5. 优化吞吐并扩展失跟恢复

针对实时速度瓶颈，将 CPU 完整网格轮廓检查改为 GPU 网格投影，并优化输入/结果保存链路。保留官方模型权重和 2 次跟踪细化；同输入 CPU/GPU 对照的保存矩阵最大逐元素差为 0，避免仅靠减少细化换取速度。

针对初始化过期和目标离场，引入初始化画面变化、深度/颜色一致性与 LK 双向光流检查，拒绝明显过时的输入。自动重获位于独立实验分支 `fix/reacquisition-sam2-eval`，没有合并主分支：

`失跟判断 → 隐藏无效位姿 → SAM2 全图候选 → 初始外观/深度尺度筛选 → 新帧一致性检查 → FoundationPose 全局重新注册 → Mask/深度验收 → 连续 3 帧确认 → 恢复跟踪`

首次仍需人工确认目标；全图候选与外观筛选不是通用语义杯子检测器。官方 top1、前 8 个注册候选与自定义几何选择分别保存。SAM2 本期用于图像候选生成，没有接入视频传播。

### 6. 用独立标记评估真实运行效果

固定杯子和实测黑边 30 mm 的 ArUco ID6，只移动相机，从同帧 RGB 独立求标记位姿。直接计算 `T_marker_from_mesh = inverse(T_camera_from_marker) @ T_camera_from_mesh`，观察固定刚体关系是否保持常量；旋转差异用 SO(3) 测地角计算。

无参考、参考质量不合格或姿态未确认时，误差留空。由于尚无独立标定的标记到网格真值变换，统计属于相对首帧的稳定性，混有参考噪声，不能称为绝对 6D 精度。之后仅按 ArUco 自身时间连续性做离线敏感性分析，不依据 FoundationPose 的大误差删帧。

|SAM2新依赖可能破坏原推理环境|独立环境、固定源码/权重、限定子进程CUDA库目录，保留原FoundationPose环境。|实际GPU分割、候选搜索和首帧闭环通过。|
|ArUco字典不匹配或码在图中太小|从原始RGB确认5×5家族ID6，新增专用入口；保持质量门限，调整视角使码短边由约20–22px达到约40px。|取得真实参考；单码抖动和平面解歧义仍限制评测。|
|参考波动与真实朝向漂移混在误差中|保留完整统计、异常样本和参考有效率；仅按参考自身连续性重算并报告保留比例。|部分位置尖峰降低，但朝向漂移仍明显，不能筛出“高精度”结论。|
|BundleSDF导出后退出139|保留真实子进程失败状态、析构日志及所有重试，不用内部report passed覆盖退出码。|未定位原生清理根因，仍未解决。|
|大数据存储和跨端档案可能遗漏/覆盖|显式纳入E盘采集树，SHA验证与run_id增量追加；项目/缓存迁E并保留联接，Git只管理代码与小报告。|相关迁移、打包、导入已验证，原始数据和失败证据保留。|

相机标定单独处理：已确认SDK内参与软件对齐路径匹配；纸盒边界检查受深度孔洞限制，后续20组棋盘采集仅1组通过既有静态/完整角点检查，未据此重拟合或覆盖设备内外参。因此物理标定精度仍未验收，不能将所有漂移归因为未手动标定，也不能宣称标定误差已排除。

### 已获得的结果

|---|---|---|

### 真实运动下仍存在的限制

固定杯子和标记的小幅移动会话中，1301个有效非锚点配对的相对位置变化均值 **10.52mm**、相对朝向变化均值 **21.16°**，P95为 **31.83mm / 72.80°**。仅按参考连续性温和离线筛选后保留1128帧（原配对86.70%），均值为 **8.73mm / 19.95°**，后段朝向仍明显漂移。

另一持续移动会话保存3720帧，1969个有效非锚点配对的相对差异均值为 **123.79mm / 89.12°**。该会话同时存在杯子朝向漂移与单码平面姿态歧义，不能与小幅移动测试直接比较精度提升比例。两组结果共同说明：运行连续、数值合法或框覆盖杯身，都不足以证明6D位姿正确。

真实ID6会话还出现过末端失跟：SAM2多次产生匹配候选，但画面持续变化或特征不足使新注册未完成。因此，目前只能声明自动重获机制已实现且通过指定回放验证，不能声明现场遮挡后的可靠恢复已经完成。

**效果定位：完成开源方法的工程复现、自有目标适配、实时推理优化与自动重获实验扩展，形成可追溯的研究原型；模型完整性、真实运动下的朝向稳定性、现场恢复成功率和绝对6D精度仍需继续优化。**

## 五、适合简历或项目介绍的表述

**项目：基于FoundationPose的六维位姿估计与目标跟踪系统**

- 基于 **FoundationPose预训练评分/细化网络与PyTorch/CUDA**，完成自有目标位姿初始化、连续跟踪和实际相机部署，最新现场连续处理约 **18FPS**。
- 结合 **几何初始化、点到面ICP与TSDF融合**，构建米制候选网格，并通过多视角重投影与尺寸检查分析几何质量。
- 集成 **SAM交互分割与SAM2全图候选搜索**，开发外观/深度约束、全局重新注册及连续帧确认的自动重获实验流程。
- 实施 **GPU网格投影加速与ArUco相对位姿评测**，优化入口回放约 **27–29FPS**，建立源码、权重、数据与运行结果的可追溯机制。

面试展开时，应说明无新增杯子网络训练、回放与现场测速区别、候选网格局限，以及相对稳定性不等于绝对精度。以上表述突出已实施的技术工作，不将待验证能力写成已达标产品性能。
